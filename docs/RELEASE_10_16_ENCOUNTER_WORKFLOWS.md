# Umoja Afya EHR 10.16.2 — Encounter Workflows, Consents and Payments

## Clinical workflow

Patient search accepts any portion of a name, MRN, MPI, telephone number or national ID. Every typed token must match the same patient identity, and exact/prefix matches rank before broader contains matches. The active country context is included in Patient Station queries.

Patient Tracker owns the next valid action:

- `WAITING_TRIAGE` opens triage for that patient and encounter.
- `TRIAGED` can be marked ready or opened directly in Provider Review.
- `READY`, `ROOMED`, `IN_PROGRESS` and `WAITING_RESULTS` open the provider workflow in the same encounter.
- Closed encounters remain available for historical review, but the API rejects new physical care against them.

Provider Review contains HPI, a body-mapped 14-system ROS, examination, assessment and plan. The ROS starts unreviewed; the clinician can explicitly attest that all systems were reviewed and negative, then tap only exceptions. Positive systems expose a focused finding field and cannot be saved without detail. This reduces repetitive interaction without silently defaulting clinical findings. Drafting or signing writes an encounter-linked clinical note and provider-visit activity. Signed-note corrections continue to use audited addenda; signed content is never silently overwritten.

The primary navigation follows patient flow: **Scheduling → Registration/ADT → Patient Care → Health Records → Radiology → Billing → Reports → Tools → Settings**. Access checks still remove modules the authenticated user is not authorized to open.

## Chart and flowsheets

The Chart Summary includes the governed 244-variable flowsheet reference grid. The full Flowsheets workspace is permanently rendered as a time-row/variable-column spreadsheet, including before the first observation. Authorized users can add, remove and reorder columns, or apply a compact governed template preset. Existing values remain in the legal history after the column layout changes.

The working encounter is selected from real patient encounters; encounter identifiers are generated by the server and are never free text. Triage and ambulatory variables are available for a live visit. Inpatient variables remain visible but locked until the same encounter has an active **Admit to inpatient service** order. The API checks both inpatient templates and inpatient-only variables placed into a mixed custom grid.

The interaction model follows ONC guidance to align documentation tools with clinical workflow and NIST human-factors guidance to evaluate realistic EHR tasks. CMS E/M guidance leaves the nature and extent of medically appropriate history and examination to the treating clinician; the bulk-negative action is therefore an explicit clinician attestation, never an automatic default. Local clinical governance must validate the workflow with representative providers before go-live.

## Registration and consent

Opening Registration from Patient Station preserves the selected longitudinal record and changes the registration form to update mode. The consent center provides governed Care, Privacy, Procedure, Testing, Research, Media, Legal and Financial forms. Evidence includes patient, optional encounter, form/version, decision, signer relationship, witness, language, timestamp and a SHA-256 signature-evidence digest.

The supplied catalog is a configurable operational starting point. The deploying health organization must approve wording, translations, witness rules, retention and jurisdiction-specific legal requirements before clinical use.

## Estimates and collections

Charges may be created as editable `DRAFT` estimates. An authorized user must explicitly finalize an estimate before it becomes a `POSTED` balance. Payments require an affirmative funds-received confirmation and an external reference for every non-cash channel. The system stores authorization or settlement references only—not a full card number, CVV, mobile PIN or crypto private key.

Configure the facility channels in `.env`:

```dotenv
UMOJA_CASH_DRAWER_ID=MNH-UPANGA-MAIN
UMOJA_CARD_TERMINAL_ID=
UMOJA_MOBILE_MONEY_TILL=
UMOJA_BANK_ACCOUNT=
UMOJA_PAYMENT_GATEWAY_ACCOUNT=
UMOJA_CRYPTO_WALLET=
UMOJA_CRYPTO_NETWORK=
```

Cash works with the configured drawer and calculates change. Card requires a terminal identifier and authorization code. Mobile money displays the configured Lipa/till destination and a QR. GePG, eCitizen, PesaLink and Remita use the payment-gateway account. Crypto displays the wallet/network and QR; staff must verify the transaction externally before confirming it.

## Upgrade on a Traefik VPS

After taking a database backup and updating `.env` channel configuration:

```bash
cd /opt/umoja-afya-ehr
git pull --ff-only
docker compose -f docker-compose.production.yml -f docker-compose.traefik.yml config --quiet
docker compose -f docker-compose.production.yml -f docker-compose.traefik.yml build --pull app transcription
docker compose -f docker-compose.production.yml -f docker-compose.traefik.yml run --rm app alembic upgrade head
docker compose -f docker-compose.production.yml -f docker-compose.traefik.yml up -d --remove-orphans
docker compose -f docker-compose.production.yml -f docker-compose.traefik.yml ps
curl -fsS https://umojaehr.online/api/v1/health/ready
```

Do not use `docker compose down -v`; the `-v` option removes persistent data volumes.

## Administrator-managed user photos

User Administration includes **Manage Photo** for the selected workforce account. Only an authenticated account whose role is `admin` and whose access matrix contains `system.users.manage` can upload or remove a photo. Individual users can view the photo assigned to them but cannot replace it. PNG, JPEG and WebP are accepted up to 2 MB; the database retains MIME type, SHA-256 digest, administrator and update time, and each change is written to the security audit trail.

# Preloaded User Roster — Release 10.7

## Security model

The release preloads account records but does not embed passwords in source code, the login page, Docker Compose, or the release archive. Deployment initialization generates cryptographically random temporary passwords in a host-protected JSON secret. Every account is marked `must_change_password=true` and `requires_mfa=true`.

## Accounts

- `platform.admin`: all five configured countries and all configured facilities.
- Country ICT administrators: `tz.admin`, `ke.admin`, `ng.admin`.
- Country operational users: registration, physician, nurse, pharmacy, laboratory, finance and operations for each country.

Examples: `tz.registration`, `ke.physician`, `ng.nurse`, `pk.physician`, `rw.registration`. Country users cannot authenticate into another country context unless ICT Administration adds that country and corresponding facility grants.

## Generate and provision

Linux/macOS:

```bash
./scripts/init-production.sh
docker compose -f docker-compose.production.yml up -d --build
```

Existing online deployment:

```bash
chmod +x scripts/provision-preloaded-users.sh
./scripts/provision-preloaded-users.sh docker-compose.production.yml
```

Review credentials are generated by `scripts/init-review.sh` or `scripts/init-review.ps1`.

## Credential handling

The generated file is `secrets/preloaded_users.json` for production or `secrets/review_preloaded_users.json` for review. Restrict it to administrators, distribute each credential separately, enforce first-login password change and MFA enrollment, then place the manifest in an approved password vault or securely delete it. Restarting containers is idempotent and never resets an existing user's password.
